Why the agent cannot bypass the policy

  1. Function-call key scope. The agent's NEAR key is a function-call access key scoped to request_spend on the agentfence contract, allowance 1 NEAR, no deposit. Calling anything else is refused by NEAR's access keys before the transaction is sent (live-verified — see the Security proof page).
  2. MPC address derives from the contract account. The MPC sign caller is the contract, and the path is evm-sepolia-<agent>. A direct MPC call by the agent would derive against the agent's account and sign for a different address — one the fence never uses.
  3. to / value / chain_id are built inside the contract. The signed EIP-1559 transaction is assembled in the contract from the policy-checked destination and amount; the agent supplies only nonce and fees, and fees are capped.
  4. The payload hash is independently verified. The contract's keccak256 signing hash matches a throwaway viem implementation byte-for-byte (scripts/verify-hash/).
