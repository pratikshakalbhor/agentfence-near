Why the agent cannot bypass the policy

Four reasons the scoped function-call key cannot move money on its own.

  1. Function-call key scope. The agent's NEAR key is a function-call access key scoped to request_spend on the agentfence contract, allowance 1 NEAR, no deposit. Calling anything else is refused by NEAR's access keys before the transaction is sent (live-verified — see the Security proof page).
  2. MPC address derives from the contract account. The MPC sign caller is the contract, and the path is evm-sepolia-<agent>. A direct MPC call by the agent would derive against the agent's account and sign for a different address — one the fence never uses.
  3. to / value / chain_id are built inside the contract. The signed EIP-1559 transaction is assembled in the contract from the policy-checked destination and amount; the agent supplies only nonce and fees, and fees are capped.
  4. The payload hash is independently verified. The contract's keccak256 signing hash matches a throwaway viem implementation byte-for-byte (scripts/verify-hash/).

For developers

Use the TypeScript SDK — five lines.

Quickstart (SDK)

import { AgentFence } from 'agentfence-sdk';

const fence = new AgentFence({
  network: 'testnet',
  contractAccount: 'agentfence-contract-evm-0b497ae1.testnet',
  agentAccount: 'agentfence-agent-9a9635f2.testnet',
  agentKeyFile: process.env.AGENT_FCK_KEY_FILE!,
});

const { address } = await fence.deriveAddress();
const result = await fence.pay({ to: '0x1111111111111111111111111111111111111111', amountWei: 1_000_000_000_000_000n });
console.log(result.decision, result.reason ?? '');

Install from this repo: npm install ./sdk (not published to npm).

MCP server

A standard stdio MCP server. Example client entry:

{
  "mcpServers": {
    "agentfence": {
      "command": "npx",
      "args": ["tsx", "mcp/src/index.ts"],
      "env": {
        "CONTRACT_ACCOUNT": "agentfence-contract-evm-0b497ae1.testnet",
        "AGENT_ACCOUNT": "agentfence-agent-9a9635f2.testnet",
        "AGENT_FCK_KEY_FILE": "/absolute/path/to/function-call-key.txt"
      }
    }
  }
}

Tools: pay, get_policy, get_spent_today, get_audit_log, get_address. pay never broadcasts unless the server starts with --allow-broadcast. A Blocked decision is a normal tool result, not an MCP error.

CLI

agentfence status
agentfence audit --limit 10
agentfence apply agentfence.policy.json --dry-run
agentfence apply agentfence.policy.json --yes
agentfence pause --yes
agentfence resume --yes

Owner-signed calls go through the near CLI with the owner key in your keychain. This tool never reads or stores owner keys.

Honest limitations

  • Spend is reserved when the signature is requested, not when the transaction is mined; a failed broadcast does not refund it.
  • Testnet only. ETH on Sepolia only.
  • No TEE — the MPC is the trust root.
  • An allowlisted destination is trusted; the fence constrains the agent, not the supplier.
  • The owner key is a single key (no multisig).
  • The injection demo uses --force-tool-call to simulate a compromised model unless run with a real LLM (agent/src/agent.ts).
  • The derived EVM address changes if the contract is redeployed to a new account.
